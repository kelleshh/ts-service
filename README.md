# TS-Service

Сервис для обучения XGBoost на одном временном ряду через HTTP API.

------------------------------------------------------------------------

## Возможности

-   Обучение модели: `POST /fit`
-   Автоподбор гиперпараметров: `POST /fit/auto`
-   Прогнозирование: `POST /predict`
-   Логирование моделей и метаданных в MLflow
-   Автоматический препроцессинг временного ряда
-   Поддержка Idempotency Key

------------------------------------------------------------------------

## Архитектура

Проект реализован как минимально достаточный ML backend для тестового задания.

В текущей версии:

-   Нет асинхронных очередей
-   Нет фоновых задач
-   Нет статусов PENDING / RUNNING
-   Нет postgres хранилища запусков

Это я бы добавил, было бы время.

`/fit` выполняется синхронно: обучение происходит сразу, затем
возвращается `model_id`.

Отдельная сущность «запуск обучения» в домене не выделялась, так как при
текущем масштабе она не несет самостоятельного бизнес-смысла.

### Возможное расширение архитектуры

Если бы проект развивался дальше, логично было б добавить:

-   TrainingRun как aggregate root
-   S3 / MinIO для хранения артефактов
-   Redis для кэширования
-   Postgres для хранения метаданных
-   Domain Events и всякие алерты
-   Мониторинг дата-дрифта
-   Непрерывное переобучение моделей
-   Асинхронность в обучении (аккуратненько)

Для тестового задания подобная сложность была бы избыточной, поэтому мною был
реализован сбалансированный вариант.

------------------------------------------------------------------------

## Тестирование

В этой версии тесты не реализованы (старые тесты остались, но они не работают), но архитектура позволяет
полностью покрыть систему.

### План покрытия (ах если бы)

### 1. Юнит-тесты

-   Препроцессинг
-   Генерация признаков
-   Политика выбора фичей
-   Разбиение train/validation
-   Расчет метрик

### 2. Интеграционные тесты

-   `/fit`
-   `/fit/auto`
-   `/predict`
-   Разные размеры временных рядов (малые и большие)
-   Разные параметры обучения

### 3. Сценарный тест

1.  Запустить обучение
2.  Получить `model_id`
3.  Проверить метаданные через MLflow
4.  Выполнить `predict` на model_id из MLFlow

### 4. E2E тест

Полный цикл: данные -> обучение -> логирование -> прогноз.

Покрытие должно быть максимальным, с разделением на unit / integration /
e2e.

------------------------------------------------------------------------

## Ограничения и проблемы текущей версии

-   Политика генерации признаков упрощена
-   Метрики на некоторых тестовых датасетах могут быть низкими (( а mape высоким :( ))
-   Контракты из `/scripts/created_contracts` можно использовать для
    ручного тестирования через Swagger
-   Нет асинхронных задач и мониторинга инференса
-   На данный момент модели чрезвычайно переобучаются на коротких горизонтах. Я примерно понимаю, в чем проблема, но пока не успел это исправить.
