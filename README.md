# TS-Service

Сервис для обучения XGBoost на одном временном ряду через HTTP API.

------------------------------------------------------------------------

## Возможности

-   Обучение модели: `POST /fit`
-   Автоподбор гиперпараметров: `POST /fit/auto`
-   Прогнозирование: `POST /predict`
-   Логирование моделей и метаданных в MLflow
-   Автоматический препроцессинг временного ряда
-   Поддержка Idempotency Key

------------------------------------------------------------------------

## Логика обучения

### /fit

- Выполняется синхронно
- Обучение происходит сразу после запроса
- Возвращается `model_id`
- Метрики считаются на train/validation через walk-forward

### /fit/auto

- Используется Optuna для подбора гиперпараметров
- Логируется лучшая конфигурация
- Возвращается `model_id`

### /predict

- Принимает `model_id` и history
- Загружает модель из MLflow
- Возвращает одно значение прогноза

---

## Препроцессинг

- Удаляются строки, где target = null
- Очистка некорректных значений (None, '', '-', inf)
- Forward-fill экзогенных признаков без утечки будущего
- Генерация признаков на основе политики размера выборки
- Разбиение train/validation с сохранением временного порядка

## Тесты

В этой версии тесты не реализованы (старые тесты остались, но они не работают), но архитектура позволяет полностью покрыть систему.

1. Юнит-тесты

-   Препроцессинг
-   Генерация признаков
-   Политика выбора фичей
-   Разбиение train/validation
-   Расчет метрик

2. Интеграционные тесты

-   `/fit`
-   `/fit/auto`
-   `/predict`
-   Разные размеры временных рядов (малые и большие)
-   Разные параметры обучения

3.  E2E тест

1.  Запустить обучение
2.  Получить `model_id`
3.  Проверить метаданные через MLflow
4.  Выполнить `predict` на model_id из MLFlow

## Переобучение модели

Политика генерации признаков упрощена, можно добавить: 
- автоматические лаги по сезонности (сначала определяем сезонность и на ее основе строим лаги); 
- в случае экспоненциального распределения - переводить таргет в логарифм в препроцессинге и потом постпроцессить обратно перед выдачей результата, чтобы масштаб для модели сохранялся;
- для финансовых рядов - фичи волатильности по типу rolling std

Препроцессинг: 
- ffill() в случае больших пропусков делать внутри сегментов, на которые разбивать ряд, чтобы большие пропуски не заполнялись просто одним числом
- сделать веса по времени (_time_weights) динамическими и включать по определенной политике (для тех же экспонент) - сейчас это костыль
- фичи вроде "time_since_last_spike", "count_spikes_last_1month"
- для экзогенов - кросс-фичи: отношения, лаговые корреляции с y (напимер corr(y_lag10, x_k_lag_10))

Тюнинг:
- изменить граинцы для Optuna (экспериментируя), так как некоторые показатели на некоторых датасетах упираются в пороги. max_delta_step можно и не тюнить, в регрессии он здесь не нужен особо.
- оптимизация mean не по фолдам, а делать робастную агрегацию. Бывают и плохие фолды (дата дрифт, аномалии), и происходит искажение оценки.
- early stopping в некоторых случаях идет не по той метрике, когда указана кастомная метрика. В objective надо возвращать именно то, что xgb использовала для early stopping: последнюю валид метрику на лучшей итерации из evals_result.
- временнЫе веса также добавить и на valid, чтобы получить взвешенную ошибку

## Чистота кода

- разспаггетизировать инфраструктурный слой, чтобы все стало более читаемо (например tuner.py), разнести функционал по файлам
- кое-где есть нарушения DRY (например обработка исключений в роутерах, много мест в инфраструктуре) - это тоже желательно унифицировать
- в инфраструктурном слое некоторые вещи считаются дважды, это полезно было бы считать в отдельной функции один раз.
- в процессе разработки некоторый функционал оказался не нужен, но он не был удален из инфраструктуры. такой мертвый груз не должен болтаться.

По-хорошему, я бы провел тщательный рефакторинг инфраструктурного слоя.

## Локальный запуск

Создание окружения:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Локальный запуск:
```bash
PYTHONPATH=src uvicorn tsfit.main:app --reload
```

Docker:
```bash
docker compose up -d --build
```

После запуска:

API: http://localhost:8000

MLflow UI: http://localhost:5000
